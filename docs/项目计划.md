# 《开源开发者活跃度与项目分布式关注调度系统》项目计划（已实现版）

> 2026-08 更新：核心工程已完成（本地自测 15/15 通过）。

---

# 一、 为什么做这个项目

一个人可能拥有多个 GitHub 账号（作品号、实验号、废弃号……）。当身体条件不再允许每天坐在电脑前，
或出于任何原因无法长期手动操作时，这些账号会停止冒泡、逐渐沉睡。

本项目让**系统代替人**，在合理、低频率、可解释的前提下继续维护数字存在：

- 每天在账号自己的 `note_repo` 里提交一条“日常笔记/签到”；
- 把“关注某个开源项目”的需求切成 **账号 × 天** 的时间片，错峰执行 star / follow / watch；
- 所有动作审计留痕，每个账号随时可「暂停 / 休眠 / 恢复」。

它也是一份给后来者的礼物：任何处境相似的人，都可以部署同样的系统，让“数字存在”
不随着无法操作而消失。

# 二、 总体架构

```
Cloudflare Cron (*/30)           浏览器（暗黑风单页控制台）
       │                                  │
       ▼                                  ▼
  scheduled() ──► runCycle(env)    GET /console（HTML 内嵌 JS）
       │                            POST/GET /api/*（JSON）
       ├─► 执行到期线程: executeTask
       │     ├─► GitHub REST: star / unstar / follow / watch
       │     └─► commit_note: 写入 note_repo/activity/日期.md
       └─► replenishNotes: 为未来 3 天各活跃账号补签到切片
                       └─► D1（6 张表）
```

- **零第三方业务依赖**：纯原生 JS (Web Crypto) 完成 TOTP / PBKDF2 / AES-GCM / HMAC 会话。
- **密文落库**：GitHub Token、TOTP 种子用 `MASTER_ENCRYPT_SECRET` 派生密钥加密；口令只存校验散列。
- **幂等可重入**：star / follow / watch 天然幂等；commit_note 用文件 sha upsert，重复执行不产生脏提交。

# 三、 数据库设计（migrations/0001_init.sql）

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `accounts` | 被守护账号 | id, username, password_hash, totp_secret_enc, github_token_enc, status(active/paused/token_invalid), mode(rule/ai), ai_persona, note_repo, timezone(+08:00), weekly_active_days, rest_until |
| `star_campaigns` | 分布式关注计划 | id, target_repo, target_user, total_target, duration_days, action_mix(star,follow,watch), account_ids, completed_count, status |
| `scheduled_actions_queue` | 分布式切片队列 | id, campaign_id, account_id, action_type, action_payload, planned_at, executed_at, status(pending/done/failed), error_msg, retry_count(0002 迁移加入，指数退避) |
| `action_pools` | 动作/文案池 | id, category, content, tag |
| `execution_logs` | 审计流水 | id, account_id, action_type, action_target, status_code, response_msg, is_success, executed_at |
| `admin_audit_logs` | 管理员操作审计（0003 迁移加入） | id, account_id, username, action(setup/login_ok/login_fail/敏感写操作), detail, ip, created_at |

种子数据：6 条 `commit_note` 日常文案 + 1 条 `stargazers` 模板。

**与原计划差异**：`password_enc` → **`password_hash`（PBKDF2，不存原文）**；时区由 `Asia/Shanghai`
改为**偏移格式 `+08:00`**（引擎需换算到 UTC）；`batch_star_campaigns` 扩展为 **`star_campaigns`**。

```

├─ wrangler.toml              # Worker + D1(DB) + Cron + nodejs_compat
├─ migrations/0001_init.sql   # 建表 + 种子文案
├─ src/
```

# 五、 核心实现说明

**1) 登录与初始化**
- 首次访问进入初始化：`/api/auth/setup` 创建管理员（可同时绑定首个 GitHub Token，仅此一次返回 otpauth）。
- 正式登录需 username + password + TOTP；会话为 HMAC-SHA256 签名 Cookie `kah`（HttpOnly/SameSite=Lax，30 天）。

**2) 加密与凭据**
- `MASTER_ENCRYPT_SECRET` → SHA-256 → AES-GCM key；`github_token_enc` / `totp_secret_enc` 格式 `v1.iv.tag.data`。
- 主密钥丢失 = 数据不可解；必须保管并预留交接方式。

**3) 活跃度机制**
- 默认每账号每天 ≤ 1 条 `commit_note`（写入 `note_repo/activity/日期.md`）。
- 每周活跃天数由「账号 id + 日期」确定性伪随机分配，让周活跃自然散开。
- `replenishNotes` 每次 Cron 为未来 3 天各活跃账号补任务，时间按账号时区（本地 08:00–13:00）。

**4) 分布式关注计划**
- `createCampaign` 生成「账号 × 天数」的可用分片，时间限制在本地 09:00–23:30，动作类型按 `action_mix` 取模轮转。
- `completed_count` 随成功递增，达 `total_target` 自动 `completed`。

**5) 审计与自愈**
- 每次执行写 `execution_logs`；HTTP 401/403 自动把账号置为 `token_invalid` 并留痕。
- 队列支持「立即执行单条」与「批量执行全部待办」。

# 六、 部署步骤（目标：Cloudflare 免费计划）

```bash
cd gitpulse
npm install

# 1. 创建 D1 数据库，把返回的 database_id 填入 wrangler.toml
npx wrangler d1 create gitpulse_db

# 2. 建表（本地 + 远程）
npx wrangler d1 migrations apply DB --local
npx wrangler d1 migrations apply DB

# 3. 设置 Secrets
npx wrangler secret put MASTER_ENCRYPT_SECRET   # 必填：32+ 随机字符
npx wrangler secret put SESSION_SECRET           # 可选，覆盖会话签名种子
npx wrangler secret put RUN_BATCH                # 可选，每次 cron 最多执行切片数

# 4. 部署
npx wrangler deploy
```

部署后访问 Worker 域名，**首次进入即初始化管理员**（otpauth 一次性，务必立即保存）。
本地调试：`npm run dev`（`.dev.vars` 放 `MASTER_ENCRYPT_SECRET` / `SESSION_SECRET`）。

# 八、 与原稿（第一版计划）的偏差

| 原设计 | 现行实现 | 原因 |
|---|---|---|
| Web 登录（authenticity_token / 2FA 序列 / CookieJar） | **GitHub REST Personal Access Token** | 更安全、幂等、减少网页结构耦合；管理员登录用 TOTP |
| 单文件 `worker.js`（后端 + UI） | 多模块工程（7 个 src 文件） | 可测试、可维护 |
| `timezone` 存时区名 | 存偏移 `+HH:MM` | 可直接换算 UTC 计划时间 |
| `password_enc` | `password_hash`（PBKDF2-200k） | 不存可还原口令 |
| `batch_star_campaigns` | `star_campaigns`（target_user/account_ids/action_mix） | 支持 follow + 多账号池 |

# 九、 安全与合规边界（务必遵守）

1. **只守护你本人所有或被明确授权的账号**：不得用于刷 star、造假、伪装大号，否则可能违反 GitHub 服务条款并牵连账号。
2. 默认频率保守（每账号每天 ≤ 1 条笔记、切片刻意错峰），任何账号可随时暂停/休眠。
3. GitHub Token 最小权限（建议 `repo`，纯 star 可只开 `public_repo`）。
4. 主密钥 `MASTER_ENCRYPT_SECRET` 丢失 = 数据不可解；请安全备份并考虑「数字遗嘱」交接。
